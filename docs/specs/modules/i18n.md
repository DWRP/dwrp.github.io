# Módulo — i18n

## Responsabilidades

- Definir locales suportados e default
- Carregar catálogos JSON e prover traduções na UI
- Persistir preferência de idioma e detectar idioma do navegador na primeira visita
- Manter seletor do Header sincronizado com o locale ativo

## Comportamento esperado

- Locales: `en`, `pt-BR`, `es`, `zh-CN` (`src/locales.ts`)
- Default de código: `en` (`defaultLocale`)
- Persistência em `localStorage` chave `preferred-locale`
- Detecção inicial: `pt*` → `pt-BR`, `es*` → `es`, `zh*` → `zh-CN`, senão `en`
- `page-content.tsx` importa dinamicamente `messages/{locale}.json` e envolve a árvore com `NextIntlClientProvider`
- `changeLanguage` atualiza hook + Zustand (`setLocale` no store)
- `document.documentElement.lang` reflete o locale atual
- Sem middleware e sem rotas `/[locale]/` (export estático)

## Restrições

- Textos de UI devem vir dos JSON; evitar hardcoded em seções
- Novas chaves devem existir nos quatro catálogos
- Não introduzir i18n server-only que quebre `output: "export"`

## Arquivos-chave

- `src/locales.ts`
- `src/hooks/useClientLocale.ts`
- `src/app/page-content.tsx`
- `src/app/sections/Header.tsx`
- `messages/en.json`, `pt-BR.json`, `es.json`, `zh-CN.json`
